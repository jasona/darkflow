# Phase 1 Step 2 Implementation Plan

Clarification gate skipped: this is a documentation-only elaboration of the
approved Phase 1 Step 2 contract. The product decision is already fixed: the
visible one-session root moves behind Vite and the existing Typia transform,
while the legacy JavaScript application remains the runtime client.

## Goal

Make the production and development `/` entry point execute a TypeScript
bootstrap generated by Vite/`@ttsc/unplugin` before it dynamically imports the
unchanged legacy `/js/app.js` module graph. The player must see the same
one-session shell, controls, assets, audio runtime, and routes; this PR changes
only how that shell is entered.

The generated root artifact must prove that a Vite bundle, not a raw
TypeScript file or direct legacy module tag, owns startup. Development must
transform the root through the same Express/Vite origin and HMR server without
changing the established API, MCP, proxy, desktop, Docker, or source-free
artifact contracts.

## Execution precondition

Step 1's local checks are green on the pinned Node 22.15.0 toolchain, but its
required hosted CI jobs are still pending
(`docs/plans/multi-connection-ui-phase-1-step-1-baseline.md:50-53`). This plan
may be reviewed now; do not start or merge its implementation until the Step 1
`baseline` and `mcp` jobs are green and their URLs are recorded.

## Evidence and constraints

- Vite already has `client/` as root and copies `public/` to
  `dist/client/`, but its only build input is the isolated Phase 0 HTML
  entry (`vite.config.ts:6-18`). The existing production `index.html` is
  therefore a copied static file whose last two scripts load Howler then
  `js/app.js` directly (`public/index.html:146-147`).
- The legacy application initializes DOM references immediately at module
  evaluation (`public/js/app.js:38-40`), so the moved root must preserve the
  complete DOM before the bootstrap imports it. Its audio manager expects the
  global Howler runtime (`public/js/howler-audio-engine.js:13-15`); the
  blocking `/vendor/howler.core.min.js` script must still precede the module
  bootstrap.
- Typia validators are hoisted in plain `.ts` modules and transformed by
  `@ttsc/unplugin` before Svelte (`client/phase0/gmcp-validators.ts:1-5`,
  `vite.config.ts:10`). The root bootstrap needs one similarly hoisted,
  exercised `typia.createValidate<BootstrapDiagnostic>()` so a raw-transform
  regression prevents startup and the existing bundle sentinel can detect it.
- The server deliberately mounts stable routes before selected frontend
  middleware and uses a replaceable Vite instance in development
  (`server.js:401-428`). `lib/dev-client.js` currently transforms only
  `/phase0/` (`lib/dev-client.js:28-55`); a root handler must be added
  without moving `/config.json`, `/api/version`, `/ping`,
  `/vendor/howler.core.min.js`, `/mcp`, or `/proxy`.
- Production validates a root `index.html`, generated version metadata, and
  the Phase 0 bundle, then compares every copied `public/` file except
  generated `version.json` (`lib/client-artifact.js:125-228`). Once
  `public/index.html` is moved, that comparison continues to prove byte
  parity for every remaining public asset; the validator must additionally
  prove the generated root bundle and legacy runtime handoff.
- Existing dev integration asserts that `/` is a byte-for-byte
  `public/index.html` response, while production integration and browser
  tests assert the built root and static contracts
  (`test/dev-server-integration.test.mjs:83-147`,
  `integration/production-server-check.mjs:209-285`,
  `e2e/production-artifact.spec.ts:60-127`). These assertions must change
  precisely to the transformed-root contract, not be removed.
- Three root-contract tests read `public/index.html` directly
  (`test/tutorial-ui-contract.test.mjs:8-22`,
  `test/howler-audio-engine.test.mjs:133-140`,
  `test/visual-effects-manager.test.mjs:530-564`). Their source assertion
  must follow the moved entry. The README also describes the root under
  `public/` and development HMR as Phase-0-only
  (`README.md:72-76, 139-185, 220-230`).
- The built production test intentionally verifies a source-free runtime and
  the desktop package ships only `dist/client/`
  (`integration/production-server-check.mjs:135-170`,
  `desktop/validate-package.cjs:84-127`). The root bundle's runtime
  `/js/app.js` import must work from copied public output, not depend on
  `client/` or Vite at runtime.

## Must-haves

- [MH1] The Vite production input includes `client/index.html` and emits
  `dist/client/index.html` with a generated JavaScript bootstrap —
  acceptance: the built root has no direct `/js/app.js` or `.ts` script
  tag, references an existing generated `assets/*.js` entry, and that entry
  contains the intentional runtime `/js/app.js` handoff.
- [MH2] The root bootstrap proves it passed through Typia transformation before
  importing legacy code — acceptance: it installs the temporary
  `window.__darkflowPhase1Bootstrap` diagnostic in a validated
  `bootstrapping` state, dynamically imports `/js/app.js` with
  `/* @vite-ignore */`, then exposes `legacy-loaded`; a missing transform
  fails the existing bundle-sentinel gate instead of shipping a broken root.
- [MH3] The player-visible root remains at parity — acceptance: development
  and built Chromium show the title, toolbar, terminal, command input, endpoint
  controls, and Howler runtime, and neither root test opens a live MUD socket.
- [MH4] Development serves transformed root HTML from the shared Express/Vite
  origin — acceptance: `GET /` and `GET /index.html` include Vite HMR and
  `/app/bootstrap.ts`; `GET /app/bootstrap.ts` is transformed JavaScript;
  desktop-cookie protection and the existing HMR/proxy upgrade dispatch remain
  intact.
- [MH5] Every remaining public file retains source parity and the built runtime
  stays source-free — acceptance: artifact verification checks copied
  `public/**` after the move, the root bundle contract, version metadata, and
  the Phase 0 bundle; production has no raw `/app/bootstrap.ts`, Vite client,
  `public/`, or `client/` dependency.
- [MH6] The new production TypeScript surface enters all applicable quality
  gates on its first PR — acceptance: `client/app/**/*.ts` is covered by
  TypeScript, ESLint, Prettier, the Vite build, and the bundle sentinel without
  adding `public/js/**` to TypeScript or reformatting legacy sources.

## Out of scope

- Session/profile/configuration models, data migration, GMCP contracts,
  transport extraction, reconnect changes, or any legacy singleton facade;
  those begin in Steps 3–13.
- Bundling, converting, renaming, formatting, or otherwise porting any
  `public/js/**` module. The bootstrap imports that graph at runtime exactly
  once.
- Replacing the visible shell, changing HTML element IDs, CSS behavior, asset
  URLs, Howler version/order, connection behavior, browser support, or the
  skipped mobile workspace suite.
- Changing the server's API/MCP/proxy behavior, packaging layout, Docker
  runtime contents, Electron behavior, CI topology, dependencies, or release
  process.
- Deleting historical Phase 0 plans or rewriting old evidence that refers to
  the former `public/index.html` location.

## Assumptions

- [Step 1's required CI jobs pass before Step 2 implementation starts] — if
  false: retain this plan as design-only and do not begin or merge Step 2.
- [Vite preserves a `/* @vite-ignore */` dynamic root-absolute import as a
  browser runtime import] — if false: add a narrowly scoped, tested runtime
  import adapter; do not let Vite pull the legacy 81-module graph into the
  bootstrap bundle.
- [The existing relative public asset URLs remain valid when `client/index.html`
  is served at `/`] — if false: convert only those root-entry URLs to
  root-absolute equivalents and prove their unchanged HTTP targets; do not
  relocate or rebundle public assets.
- [The temporary bootstrap diagnostic is acceptable until the Step 13
  compatibility cutover] — if false: Step 2 needs a different observable
  transform proof and must be re-planned before implementation.
- [No deployed page depends on fetching the source file
  `/public/index.html`] — if false: retain a server-side compatibility route
  only if it does not bypass the transformed `/` entry; otherwise obtain a
  product decision before removing the source file.

## Risks

- Vite may resolve the legacy import as a build dependency and accidentally
  bundle or rewrite it. Mitigation: use the explicit `@vite-ignore` runtime
  import, assert the generated bundle contains `/js/app.js`, and preserve
  source parity for copied legacy modules.
- An HTML move can break DOM timing, asset paths, or Howler availability before
  legacy imports execute. Mitigation: move markup without reformatting, replace
  only the final module tag, retain the classic Howler tag before it, and assert
  the full root shell in development and production.
- An explicit dev root route can shadow API/MCP/proxy/static routes or survive
  a dev-to-built restart. Mitigation: retain the existing middleware ordering,
  add only `/` and `/index.html` selected-route state, and reset it with the
  other dev lifecycle fields.
- Artifact validation could become permissive merely because
  `public/index.html` no longer exists. Mitigation: add a separate generated
  root-bundle validator and negative fixtures for direct legacy scripts, raw
  TypeScript, missing generated assets, and missing runtime handoff.
- The move can leave source-reading tests or documentation stale. Mitigation:
  update each verified source reader and current developer documentation in the
  same PR; historical plan evidence remains untouched.

## Steps

### Step 1 — Create the transformed root entry and scoped bootstrap

**Files:** `client/index.html` (new), `client/app/bootstrap.ts` (new),
`public/index.html` (moved/removed), `vite.config.ts`, `tsconfig.json`,
`eslint.config.mjs`, `package.json`, `test/vite-config.test.mjs`,
`test/tutorial-ui-contract.test.mjs`, `test/howler-audio-engine.test.mjs`,
`test/visual-effects-manager.test.mjs`, `README.md`, `CLAUDE.md`

**Intent:** Move the root markup to `client/index.html` without reformatting
or changing its DOM, CSS, favicon, manifest, image, or legacy asset URLs.
Retain the classic `/vendor/howler.core.min.js` script and replace only the
final direct legacy module tag with the Vite entry
`/app/bootstrap.ts`.

In the bootstrap, define a small `BootstrapDiagnostic` interface and hoist
`typia.createValidate<BootstrapDiagnostic>()` in the plain `.ts` module.
Validate and expose a temporary `window.__darkflowPhase1Bootstrap` object
with `phase: "bootstrapping"` before
`await import(/* @vite-ignore */ "/js/app.js")`; update it to
`phase: "legacy-loaded"` only after the import resolves. Do not import any
`public/js/**` module statically or add session behavior.

Add the root HTML input alongside `phase0` in the Vite configuration. Expand
the client typecheck/lint/format globs to include the new production TypeScript
surface while leaving the legacy JavaScript style boundary intact. Update the
three source-reading tests to read `client/index.html`; the Howler test must
also assert classic Howler precedes the bootstrap and the bootstrap owns the
legacy handoff. Update current README/CLAUDE development and layout text to say
the root shell is Vite-transformed while legacy assets/modules remain under
`public/`.

**Verify:**

```bash
npm run format:check
npm run lint
npm run typecheck
npm run check
node --test test/vite-config.test.mjs test/tutorial-ui-contract.test.mjs test/howler-audio-engine.test.mjs test/visual-effects-manager.test.mjs
npm run build
npm run verify:bundle
```

**Done when:** `dist/client/index.html` names a generated root bundle, not
`js/app.js` or `.ts`; the bundle sentinel scans the bootstrap's transformed
Typia code successfully; the legacy shell source is unchanged except for its
entry-module handoff; and every directly HTML-reading test targets the moved
file.

### Step 2 — Serve the transformed root through the shared dev server

**Files:** `lib/dev-client.js`, `server.js`,
`test/dev-server-integration.test.mjs`,
`integration/production-server-check.mjs`

**Intent:** Generalize `attachDevClient`'s explicit HTML transformer into
separate root and Phase 0 handlers. The root handler reads
`client/index.html`, calls `vite.transformIndexHtml("/", html)`, and serves
only the selected development root; Phase 0 behavior remains unchanged.

Add replaceable root-route state in `server.js` for `/` and
`/index.html`, after existing stable-route/static/Vite dispatch and alongside
the Phase 0 selected handler. Set and clear it on dev start/stop with the
existing Vite lifecycle state. In built mode, leave Express static serving
`dist/client/index.html` unchanged. Do not alter the route or upgrade order
for `/config.json`, `/api/version`, `/ping`, `/vendor`, `/mcp`, or
`/proxy`.

Update dev integration to expect transformed root HTML with the Vite client and
`/app/bootstrap.ts`, transformed bootstrap JavaScript, root/index desktop
cookie protection, and unchanged Phase 0/HMR/proxy behavior. Update the
production integration to prove the built root has a generated bundle and that
`/app/bootstrap.ts` is unavailable in built mode, while preserving all
existing static/API/proxy/source-free assertions.

**Verify:**

```bash
node --test test/dev-server-integration.test.mjs
npm run build
npm run test:server:built
```

**Done when:** development `/` and `/index.html` are Vite-transformed on
the shared origin; development `/app/bootstrap.ts` is JavaScript; built
`/` is the generated artifact and returns no source/HMR route; a dev-to-built
restart leaves no stale Vite handler; API/MCP/proxy route and upgrade tests pass.

### Step 3 — Strengthen generated-root artifact validation

**Files:** `lib/client-artifact.js`,
`test/client-artifact.test.js`,
`scripts/verify-client-artifact.mjs` (only if its call signature needs
adjustment)

**Intent:** Keep the existing version and Phase 0 checks, then add a root-entry
validator that parses `dist/client/index.html`. It must reject a root that
directly loads `/js/app.js` or any `.ts` file; require at least one generated
`assets/*.js` script, require every referenced generated script to exist, and
require a referenced root bundle to contain both the temporary diagnostic key
and the Vite-ignored `/js/app.js` handoff. Continue comparing every file that
remains in `public/` byte-for-byte, except generated `version.json`; do not
replace this with a broad exclusion list.

Refactor fixture setup so the source `public/` tree has assets but no
`index.html`, and the artifact root is a Vite-like HTML/bundle pair. Add
positive coverage plus negative fixtures for a missing root bundle, an absent
referenced asset, a raw TypeScript root entry, a direct legacy module tag, and
a generated bundle without the legacy runtime handoff. Keep all existing Phase
0 and source-parity cases.

**Verify:**

```bash

npm run build
npm run verify:client-artifact

```

**Done when:** artifact validation proves both independent Vite entries and

## Rollback

No player data, server protocol, or published artifact changes are irreversible.
Revert the Step 2 PR as one unit to restore `public/index.html`, remove the
root Vite input/bootstrap/dev route, and reinstate the previous source-parity
and test expectations. The prior built artifact or package remains a safe
deployment rollback until a new artifact passes all gates.
