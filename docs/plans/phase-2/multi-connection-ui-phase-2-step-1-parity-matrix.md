## Evidence and row rules

- `AUTOMATED` names an existing command and test or fixture. Its `PASS` result
  is limited to the candidate and exact behavior stated in the row.
- `MANUAL` names environment, actions, and observation. No live Darkwind check
  is an automated gate.
- `MISSING` names the smallest proof the owning step must add; its candidate
  result is `NOT_RUN`.
- Facets use `COVERED`, `MISSING`, or `NOT_APPLICABLE` with a reason. They are:
  built web, Electron, mobile/touch, keyboard/focus/accessibility/theme,
  reconnect, and disposal.

Each ledger row has the required fields: stable ID; observable behavior;
current owner; baseline evidence and candidate result; a single Phase 2 owner;
facets; an exact cutover condition; and concrete rollback.

## Cutover rule

Steps 2-11 may append replacement evidence and mark only their own rows green.
They must preserve the listed legacy source or storage input and must not make
the replacement the production root. Step 12 is the only production cutover:
it requires every required row and every Step 12 release row green for one
immutable Phase 2 candidate. A failed row restores the row's rollback target;
the pre-cutover artifact remains the global rollback path.
